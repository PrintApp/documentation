Add a **File upload** field to any section and your customers can attach their
artwork to the job. The file travels with the order, so your production team
receives the specification and the artwork together.

## Basic uploads

Out of the box, a file field accepts the file types you list (PDF by default),
uploads it securely, and records the filename against the order.

### File types

Customers can upload these formats, up to **100 MB** per file:

| Format | Extensions |
| --- | --- |
| PDF | `.pdf` |
| JPEG | `.jpg`, `.jpeg` |
| PNG | `.png` |
| TIFF | `.tif`, `.tiff` |
| SVG | `.svg` |
| Illustrator | `.ai` |
| EPS | `.eps` |
| Photoshop | `.psd` |
| ZIP | `.zip` |
| Word | `.doc`, `.docx` |
| Excel | `.xls`, `.xlsx` |
| CSV | `.csv` |

Choose what each file field takes in its **Accepted types**, separated by
commas. Write them however is easiest: format names (`PDF, Word`),
extensions (`.pdf, .zip`) or MIME types (`application/pdf`) all work. The
builder shows what your entry allows as you type ("Customers can upload: PDF,
ZIP").

What your customers see:

- **The file picker** offers only those types.
- **A file of another type**, picked or dragged in, isn't uploaded. The field
  shows *Accepted file types:* followed by the formats it takes, in the
  customer's language.
- **Your text** is shown under the dropzone as you wrote it, so you can phrase
  it for your customers (`PDF, Word, JPG`).

<Note>
    If **Accepted types** names none of the formats above, the field takes any
    of them. To limit a field, list the formats you want. With
    [Filecheck](#filecheck-validated-uploads) connected, Filecheck's intake
    decides which files it takes, because it checks their contents.
</Note>

### Several files

To let customers attach more than one file, for example artwork plus
fonts, a set of photos, or artwork and a mailing list, either:

- **Allow multiple files on one field.** Select the File upload field and
  turn on **Allow multiple files**, then set **Maximum files** (2 to 10,
  5 by default). Customers can pick or drop several files at once; each one
  is listed with **Remove**, and the field stops taking files at the
  maximum.
- **Add several File upload fields**, each with its own label, such as
  *Artwork* and *Mailing list*. Each field keeps its own file.

Every file reaches the order with its own **Download file** link. When an
order has more than one file, each link names its file. Files are
attachments: they don't change the price.

<Note>
    Multiple files apply to direct uploads. A field connected to
    [Filecheck](#filecheck-validated-uploads), or set to **Designer only**,
    holds one artwork.
</Note>

### Storage and downloads

Uploaded files are stored for **30 days** and then removed automatically. Print
Options is a configurator, not a file archive — download what you need into your
production workflow.

Each order line with an upload has a **Download file** link: a button under
the line on the WooCommerce order screen, and a line property on the Shopify
order. See
[Downloading customer uploads](/print-options/guides/cart-and-orders#downloading-customer-uploads).

<Tip>
    Need customers to accept an artwork declaration or your terms before they
    upload? See
    [Requiring an agreement before upload](/print-options/guides/fields#requiring-an-agreement-before-upload).
</Tip>

## Filecheck-validated uploads

[Filecheck](https://apps.shopify.com/filecheck) is our upload preflight
service. Connected to a file field, it replaces the plain dropzone with an
intake that actually inspects the file — and hands back facts your pricing can
use:

| Fact | What it unlocks |
| --- | --- |
| **Page count** | Per-page pricing for booklets, theses, documents. |
| **Colour vs mono pages** | Charging colour and black-and-white pages differently. |
| **Canvas size** | Area pricing taken from the artwork itself. |
| **Preflight issues** | Catching bad files before they reach production. |

The moment Filecheck reports on a file, the price updates: a 64-page thesis
prices itself the instant the PDF lands.

<Note>
    Filecheck is optional and separate. Without it, uploads still work — you
    just price by what the customer tells you rather than what the file
    contains.
</Note>

### Connecting Filecheck

1.  Set up your product in [Filecheck](https://filecheck.io) and copy your
    **publishable key**.
2.  Add it in Print Options:
    - **Shopify** — theme editor, Print Configurator block, *Filecheck
      publishable key*.
    - **Wordpress** — `Print Options` → `Settings` → *Filecheck publishable
      key*.
3.  In the builder, select your file field and set its provider to Filecheck.

The publishable key is designed to be public and browser-safe — it identifies
your account, it does not grant access to it.

## Pricing from file facts

Once a file field reports page counts, use the matching price changes on your
choices:

- **Per page** — every page, times the quantity.
- **Per colour page** / **Per mono page** — split rates, so colour costs what
  colour costs.

A typical thesis set: a base binding charge as a fixed amount, then per-page
rates on the colour choice.

<Tip>
    Combine with [tiered pricing](/print-options/guides/pricing): per-page rates
    can carry quantity breaks, so long documents get cheaper per page.
</Tip>

## Artwork from the Print.App designer

If your product also uses the [Print.App designer](/introduction), customers
can design their artwork online instead of uploading a file. The designer's
button appears in the configurator's artwork step, and the finished design
becomes the job's artwork, with its page count available to your
pricing.

How the button finds its place:

- **With a File upload field**, the designer's button sits in that field,
  next to the upload. To offer *only* the designer, set the field's
  **Display** to **Designer only (no direct upload)**. Customers then see the
  designer button and no dropzone.
- **Without a File upload field**, the configurator adds an artwork step of
  its own when the designer is on the page, titled with the designer's button
  label (*Design online*, say). It is optional; whether a design is required
  is set in Print.App.

Once a design is saved, the step shows *Your design* (in the customer's
language) with **Change** and **Remove**, and the order reads *Design online:
Your design*. The page count is shown only when your pricing uses
them.

<Tip>
    Connectors pass values between the designer and the configurator: the
    number of printed sides into a *Sides* choice, the chosen size into the
    designer, and more. See
    [Connectors](/configuration/connectors).
</Tip>
