<Tip>
Using an AI agent? Give it the [Quickstart for agents](/mcp/quickstart-agents) and it sets this up for you.
</Tip>

The Print.App MCP server lets AI tools work in your Print.App account.

```
https://api.print.app/mcp
```

## What you can do

- **Designs:** create templates at a print size with bleed and a safe area, add text, images, shapes, QR codes and calendars, and look at the result.
- **Graphics, fonts and colours:** upload images and SVGs, import Google fonts, and set up palettes.
- **Products:** list your Shopify or BigCommerce products, choose which designs each one opens, and make project URLs to share or test a design.
- **First setup:** ask *"use Print.App to show me how it works on my store"* and your assistant takes one product from choosing it to testing it as a customer, checking with you at each step. Ask *"set up my Print.App store with me"* to go through every product, then your logo, fonts and colours.
- **Connectors:** make the editor follow the options on your product page (front, back or both; a design per size; the shirt colour), tested choice by choice. See [Set up connectors with AI](/mcp/connectors).
- **Options and prices:** give a Shopify product its sizes, papers, quantities and prices with [Print Options](/print-options/introduction), every price checked with you before it goes live, and link the design customers personalise. See [Set up Print Options with AI](/mcp/print-options).
- **Profiles:** limit the fonts, colours and graphics some designs offer, and set how their print PDFs are made.
- **Library:** ready-made designs and graphic kits from the Print.App library, found by what your product is for and its size, and imported into your account.
- **3D scenes:** which product a design is shown on in 3D, checked against the design's pages and size.
- **Settings:** how the editor opens and behaves, and fixing a Customize button or previews that don't show on your product page.
- **Projects:** find your customers' saved designs and their print files, and fix what is on their pages (a submitted one only when you agree).

## Before you start

Create a secret key in your admin under [Secret keys](https://admin.print.app/api-keys), labelled for the tool you connect. Revoking it later disconnects that tool.

## ChatGPT

1. **Add the server:** turn on developer mode and add a custom MCP server ([OpenAI's guide](https://help.openai.com/en/articles/12584461-developer-mode-and-mcp-apps-in-chatgpt) shows where, for your plan). Name it Print.App, use the URL `https://api.print.app/mcp` and choose **OAuth** authentication.
2. **Connect:** ChatGPT opens a Print.App page. Paste your secret key and click **Allow access**.
3. **Test:** ask *"Which Print.App store am I connected to?"*

<Note>
ChatGPT keeps the list of tools it saw when you added the server. When Print.App adds new tools, open the connection at [chatgpt.com/plugins](https://chatgpt.com/plugins) (or Settings, then Apps), click **Refresh**, and start a new chat. On a Business or Enterprise workspace, an admin may need to refresh it.
</Note>

## Claude

1. **Add the server:** in Claude (web or desktop), open **Settings → Connectors** and click **Add custom connector**. Name it Print.App and use the URL `https://api.print.app/mcp`.
2. **Connect:** click **Connect**. Paste your secret key on the Print.App page and click **Allow access**.
3. **Test:** ask *"Which Print.App store am I connected to?"*

## Claude Code

1. **Add the server:**

    ```bash
    claude mcp add --transport http --scope user printapp https://api.print.app/mcp \
      --header "Authorization: Bearer sk_…"
    ```

2. **Check it:** run `/mcp` in Claude Code; `printapp` shows as connected.
3. **Test:** ask *"Which Print.App store am I connected to?"*

## Codex

1. **Add the server** to `~/.codex/config.toml`:

    ```toml
    [mcp_servers.printapp]
    url = "https://api.print.app/mcp"
    bearer_token_env_var = "PRINTAPP_SECRET_KEY"
    ```

2. **Set the key** in your shell profile: `export PRINTAPP_SECRET_KEY=sk_…`
3. **Test:** start Codex and ask *"Which Print.App store am I connected to?"*

## Cursor

1. **Add the server** to `~/.cursor/mcp.json` (your global settings, so the key never lands in a project):

    ```json
    {
      "mcpServers": {
        "printapp": {
          "url": "https://api.print.app/mcp",
          "headers": { "Authorization": "Bearer sk_…" }
        }
      }
    }
    ```

2. **Check it** in Cursor's MCP settings: `printapp` shows its tools.
3. **Test:** ask *"Which Print.App store am I connected to?"*

## VS Code

1. **Add the server** to `.vscode/mcp.json`. VS Code asks for the key when it starts the server, so the file holds no secret:

    ```json
    {
      "inputs": [
        { "type": "promptString", "id": "printapp-key", "description": "Print.App secret key", "password": true }
      ],
      "servers": {
        "printapp": {
          "type": "http",
          "url": "https://api.print.app/mcp",
          "headers": { "Authorization": "Bearer ${input:printapp-key}" }
        }
      }
    }
    ```

2. **Start it:** run **MCP: List Servers**, choose `printapp`, start it and paste your key.
3. **Test:** in chat (agent mode), ask *"Which Print.App store am I connected to?"*

## Other MCP clients

Any client that supports remote MCP servers over Streamable HTTP can connect, either way:

- **Sign in (OAuth):** the client finds the sign-in on its own. Its redirect URI must be an `https` address.
- **Send the key:** as the header `Authorization: Bearer sk_…`.

Details for developers, including the OpenAI and Claude APIs, are in the [MCP reference](/api-reference/v2/mcp).
