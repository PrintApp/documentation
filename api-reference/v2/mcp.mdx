<Tip>
Just want to connect? Follow [MCP server](/mcp/server), or hand your agent the [Quickstart for agents](/mcp/quickstart-agents).
</Tip>

Print.App runs a remote [Model Context Protocol](https://modelcontextprotocol.io) server, so AI agents such as ChatGPT, Claude, Cursor or your own can work in your account through the [REST API](/api-reference/v2/introduction): build a design from a brief, look at it and fix it, then put it on a product.

```
https://api.print.app/mcp
```

A client connects one of two ways, both with a [secret key](/api-reference/v2/authentication) of your store:

- **Sign in (OAuth):** apps such as ChatGPT and Claude open a Print.App page where you paste the key and allow access. The app never sees the key: it gets its own access, tied to that key.
- **Send the key:** developer tools and your own code send `Authorization: Bearer sk_…` with every request.

<Warning>
An agent connected with your key can change and delete anything in your account that the API can. Create a separate key for each app or agent, labelled so you recognise it. Revoking the key in the admin disconnects it, including apps that signed in with it.
</Warning>

## Connect a client

<Tabs>
  <Tab title="ChatGPT">
    1. In ChatGPT, add a custom MCP server (it is in developer mode; see OpenAI's [Connecting custom MCP servers in ChatGPT](https://help.openai.com/en/articles/12584461-developer-mode-and-mcp-apps-in-chatgpt) for where it is on your plan).
    2. Name it Print.App, enter the URL `https://api.print.app/mcp`, and choose **OAuth** as the authentication.
    3. ChatGPT opens the Print.App connect page. Paste a secret key of your store and click **Allow access**.

    ChatGPT keeps the tools it saw when you added the server. When Print.App adds tools, click **Refresh** on the connection at [chatgpt.com/plugins](https://chatgpt.com/plugins) and start a new chat.
  </Tab>
  <Tab title="Claude">
    In Claude (claude.ai or the desktop app), add a custom connector with the URL `https://api.print.app/mcp`, then click **Connect**. Claude opens the Print.App connect page: paste a secret key of your store and click **Allow access**.
  </Tab>

  </Tab>
  <Tab title="OpenAI API">
    With the [remote MCP tool](https://developers.openai.com/api/docs/guides/tools-connectors-mcp) of the Responses API:

    ```json
    {
      "tools": [{
        "type": "mcp",
        "server_label": "printapp",
        "server_url": "https://api.print.app/mcp",
        "authorization": "sk_…",
        "require_approval": "never"
      }]
    }
    ```

  </Tab>

Any MCP client that speaks Streamable HTTP works the same way, sending a key or signing in. The server is stateless: it answers JSON over `POST` and keeps no sessions.

### How signing in works

Clients find the sign-in on their own: a request without credentials gets a `401` that points to `https://api.print.app/.well-known/oauth-protected-resource/mcp`, and from there to the authorization server, `https://auth.print.app`, and its metadata at `https://auth.print.app/.well-known/oauth-authorization-server`. It supports dynamic client registration and client ID metadata documents (for public clients, and for clients that sign with `private_key_jwt`, as ChatGPT does), PKCE (S256) and refresh tokens. Access lasts an hour and the client renews it on its own; it stops within a minute of the key it was approved with being revoked.

Redirect URIs are `https` addresses, as ChatGPT's and Claude's are, or a local address for apps on your computer such as Claude Code (`http://localhost:…/callback` or `http://127.0.0.1:…/callback`, on any port).

## What an agent can do

| Area | Tools |
| --- | --- |
| Account | `get_account` |
| Designs | `list_designs`, `get_design`, `create_design`, `update_design`, `duplicate_design`, `delete_design`, `manage_pages` |
| Page content | `get_design_content`, `edit_design`, `design_ops_reference`, `preview_design` (a design's, or a customer project's with `projectId`) |
| Design folders | `list_design_folders`, `manage_design_folder` |
| Files | `list_files`, `get_file`, `upload_file`, `manage_file` |
| Graphic folders | `list_graphic_folders`, `manage_graphic_folder` |
| Fonts | `list_fonts`, `manage_font` |
| Palettes | `list_palettes`, `manage_palette` |
| Products | `list_store_products`, `list_products`, `get_product`, `set_product_designs` |
| Connectors | `inspect_product_page`, `test_connector`, `list_connectors`, `manage_connector` |
| Profiles | `list_profiles`, `get_profile`, `manage_profile` (resource and PDF profiles) |
| 3D scenes | `list_scenes` |
| Library | `search_library_designs`, `import_library_design`, `search_library_graphics`, `import_library_graphics` |
| Settings | `get_settings`, `update_settings` |
| Projects | `list_projects`, `get_project`, `manage_project` |
| Project URLs | `create_editor_link`, `get_editor_link`, `expire_editor_link` |
| Print Options | `list_option_sets`, `get_option_set`, `quote_option_set`, `manage_option_set`, `print_options_reference` |

Each tool calls the REST API with your key, so the same rules, limits and errors apply. Tools that only read are marked read-only; every tool that creates, changes or deletes something is marked destructive, so clients that ask before running those will ask.

`update_design` also sets what a design uses (its connectors, resource profiles, PDF profile and 3D scene) and its own settings over the store's. Given a scene, it says whether the scene suits the design.

The server also offers three prompts, for clients that list MCP prompts:

- `set_up_store` (*Set up my store*): a quick look with one product, or the whole store with `scope` set to `store`, as described below.
- `set_up_connector` (*Set up a connector*): it takes a product page and a goal, and writes out the connector steps below for the agent.
- `set_up_print_options` (*Set up product options and prices*): a product's options and prices with [Print Options](/print-options/introduction), as described below.

Clients that don't show prompts, such as ChatGPT, get the same steps from the server's instructions.

## How an agent sets up a new store

There are two ways to start, and the agent checks in with you at each step of both. In Claude, the `set_up_store` prompt does the same: its `scope` is `product` (the default) or `store`.

**A quick look** at one product needs only the Print.App connector. Ask *"Use Print.App to show me how it works on my store: help me pick one of my products, start from a Print.App design template that fits it, show it to me, then link it and give me the link to test it as a customer."* (or *"on this product"* with its page link):

1. `get_account` says which platform your store is on. On Shopify and BigCommerce, `list_store_products` lists your products to choose from; on other platforms the agent asks for the product page link.
2. `inspect_product_page` reads the product's size, sides and options.
3. `search_library_designs` finds design templates at that size; the agent shows you two or three and imports the one you pick with `import_library_design`, or makes one with `create_design` if none fits.
4. `preview_design` shows it, with one round of changes if you ask.
5. After asking you, `set_product_designs` links it to the product.
6. You get the product page link to test it as a customer, and the agent offers to set up the rest of your store. If the product page can't show the design yet (a password-protected store, a product you'd rather not link yet), you get a project URL to test it instead.

**The whole store**: ask *"Set up my Print.App store with me. Go through my products one by one…"*. The agent starts with the product you sell most, as in the quick look, and gives you its link to test straight away. Then it goes through your other products one at a time, sets up connectors for their size, page and sides options, adds your logo, fonts and colours, and changes editor settings or 3D scenes only where they help. It finishes with a summary of what is live.

If your assistant also has your store's own connector (Shopify's, for example), the agent can use it to read your products and variants, and to create or fix them after asking you. It is never required, and prices stay with your store: Print.App never sets them.

It never needs your secret key in the chat: the key goes into your assistant's settings or Print.App's sign-in page.

## How an agent fixes a customer's project

`get_design_content`, `edit_design` and `preview_design` take a `projectId` instead of a `designId`, so an agent can fix a typo, swap a photo or change a colour on a customer's project. The project's PDF follows the edit; its order details, product and `userData` stay as they were.

- A **submitted** project (added to the cart or ordered) is refused unless the edit sends `allowSubmitted: true`, since it changes what is printed for that order. The agent asks you first.
- A **mail-merge** project is refused: it prints from its mail-merge pages. Open it in the editor with a project URL (`create_editor_link` with its `projectId`) instead.
- The cart or order thumbnail a store saved when the customer ordered keeps the old image; the project's own previews and PDF show the edit.

Try it with *"On the project for order 1042, change the phone number to 555 0100, show me, and ask before you save."*

## How an agent builds a design

1. `create_design` at the trim size, with bleed and a safe margin.
2. `upload_file` for logos, photos and SVG graphics.
3. `get_design_content` to read the page size and safe area, then `edit_design` with a batch of operations: text, shapes, graphics, photo frames, QR codes, calendars. The batch saves as one change, or not at all.
4. `preview_design` returns images of the pages, so the agent can look at its work and fix what it sees with another `edit_design`.
5. `set_product_designs` to sell it on a store product, or `create_editor_link` for a project URL to share it or test it as a customer.

Try it with a prompt like *"Create a two-sided 85 × 55 mm business card for a bakery called Crumb & Co with 3 mm bleed: logo from https://…/logo.png, the name, job title and phone as fields customers fill in, and a warm palette. Show me both sides."*

## How an agent starts from the library

The Print.App library is the catalogue of ready-made designs and themed graphic kits that the dashboard's Import Designs and Import from Library open. An agent can start from it instead of a blank page:

1. `search_library_designs` with what the product is for and its trim size. Each design says how its size compares (`sizeMatch`), and `sameSize` keeps only designs at the product's size. The agent can show you the thumbnails to choose from, or look at them itself with `showImages`.
2. `import_library_design` copies your choice into your account, as a design of your own. It can then edit it, preview it and put it on a product like any other.
3. `search_library_graphics` finds graphics and kits; `import_library_graphics` adds a whole kit to your editor's Pictures (it follows the kit, so new graphics in it appear too) or single graphics to a folder.

Try it with *"Find me a few Christmas card designs at 5 × 7 inches, show them to me, and import the one I pick."*

## How an agent sets up a connector

1. `inspect_product_page` reads the product page of your store: each option control with a selector that finds it and the choices it sends, the Print Options fields with their roles, and the designs the product opens.
2. `get_design` and `preview_design` show the design's pages.
3. `test_connector` plays the connector, before it is saved, against the design for every choice: what the page sends, which mapping matches, what the editor does, with images of the pages each choice shows. It reports what stands in the way: a selector that finds nothing, choices without a mapping, pages the design doesn't have, a design that isn't on the product, another connector fighting this one.
4. `manage_connector` saves it and attaches it to the designs (`create` with `designIds`), and `test_connector` runs once more with its id.

The walk-through for store owners is [Set up connectors with AI](/mcp/connectors).

## How an agent sets up Print Options

[Print Options](/print-options/introduction) is Print.App's free product options app: the sizes, papers, sides, quantities and prices customers choose on a product page, priced again on our servers when they add to cart. On a Shopify store with both apps installed, the same agent sets up the options, the design and the link between them:

1. `list_option_sets` says whether option sets can be managed for your store (and if not, why), your store's currency, and what is published on which products.
2. `print_options_reference` explains how an option set is written and lists the templates (Business Cards, Flyers, Booklets, Stickers, Posters…); with a template, it returns one to adapt. The agent sets your currency, your choices and your prices, and gives the size, pages, material and orientation fields their role.
3. `quote_option_set` prices typical orders with the engine that prices the cart, line by line. The agent shows you a price table and changes nothing until every price is right.
4. After asking you, `manage_option_set` publishes the option set to your products. `dryRun` shows first what would change, including products that would move from another option set.
5. `set_product_designs` links a design, and the Print.App editor fills the options' artwork step by itself.
6. Connectors only where the design should follow an answer, by role: a field with role `orientation` sets the page orientation with no connector; a size choice can open another design (`designSelector`) or show other pages (`pageIndex`); a dimensions field can size the canvas (`pageWidth` and `pageHeight`); a pages field can follow the design's page count (`pageCount`, sent from the editor to the product page). `test_connector` checks each first.

Try it with *"Set up flyer options on my Flyers product with Print Options: A5 and A4, 130 g or 300 g paper, 100 to 1000 copies. My prices are in this list: … Show me the prices before anything goes live, then link a flyer design."*

Option sets an agent publishes are ordinary ones: open them in Print Options, under **Products**, to change them yourself. On WooCommerce, build option sets in WordPress for now; `quote_option_set` and the templates work for any store, so an agent can still write and price an option set for you to import (**More → Import JSON…** in the builder).

## Things to know

- **New tools** reach Claude and other clients when they reconnect. ChatGPT needs its connection refreshed (**Refresh** at [chatgpt.com/plugins](https://chatgpt.com/plugins)), then a new chat.
- **Page content** can only be edited on accounts that use the new editor. Others get `editor_not_supported`.
- **SVG graphics go in as files.** The firewall in front of the API refuses requests that carry markup, so an agent should upload an SVG with `upload_file` and place it as an `asset`, not write SVG into an operation. It stays vector in print. A tool call with SVG or HTML in its arguments fails with an HTTP `403` before it reaches the server, so the client reports a connection error rather than a tool error.
- **Fonts** must be families your account has. `list_fonts` lists them; `manage_font` imports any Google font.
- **Previews** are redrawn each time a design is saved. They are for checking a layout; the PDF is made from the design itself.
- **Library** designs come into your account as copies: changing yours never changes the library's. Kits and graphics come in as links, so they don't use your storage.
- **3D scenes** are made in the dashboard. `list_scenes` lists yours and the library's and, given a design, checks each against it: a print area showing a page the design doesn't have, a folded leaflet with no inside page, a fixed size that doesn't match. A scene that doesn't suit can still be set; the editor shows what it can.
- **Settings** that run code in your store (custom JS and CSS), send data elsewhere (webhook addresses) or delete customers' projects can't be changed through the MCP or the API, and the editor in use is read-only: change those in the dashboard. `update_settings` is marked destructive, so clients ask before running it.
- **Print Options on Shopify** shows through the theme's **Print Configurator** block, added once per theme (Online Store → Themes → Customize → Add block → Apps). Until it is there, published options don't show; `inspect_product_page` lists a product's Print Options fields once they do. Option sets must be priced in the store's default currency, or the cart refuses them.
- **Product pages** are read as your server sends them, and only pages of your own store. Options a theme builds in JavaScript after the page loads aren't seen; a store behind a password answers with its password page (give `test_connector` the choices as `values` instead).
